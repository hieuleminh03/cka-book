## Cách dùng chương này {#cach-dung-chuong-nay}

Các chương trước đã trang bị kiến thức và lab theo từng domain. Chương này là lúc bạn **kiểm tra thật**: hai bộ đề mô phỏng đúng kiểu đề thi performance-based của CNCF, một bộ cho CKA và một bộ cho CKS, mỗi bộ 12 task trên cluster kind 3 node với các tình huống "đã bị hỏng sẵn" — bạn phải tự chẩn đoán, tự sửa và tự chứng minh.

Cách dùng hiệu quả:

1. Dựng môi trường theo hướng dẫn bên dưới, **không đọc trước nội dung task khi script đang chạy** để giữ tính bất ngờ khi làm bài.
2. Bấm giờ đúng 2 giờ cho một bộ; chỉ dùng tài liệu được phép như thi thật (chủ yếu là `kubernetes.io/docs`).
3. Chấm điểm theo hướng dẫn ở [Cách chấm điểm](#cach-cham-diem), sau đó mới mở [lời giải](ch17a.html) để so từng bước.
4. Ghi lại mọi task quá 10 phút hoặc làm sai vào một file riêng, rồi học lại chương tương ứng trước khi làm bộ tiếp theo.

Hai bộ đề độc lập nhau: bạn có thể làm Set A trước, nghỉ 15 phút, làm Set B; hoặc tách thành hai ngày. Nếu thời gian eo hẹp, hãy làm trọn một bộ thay vì làm nửa hai bộ — kỹ năng quản lý thời gian chỉ luyện được khi bấm giờ trọn vẹn.

### Luật chơi của mock exam {#luat-choi-cua-mock-exam}

- **Thời gian:** 2 giờ cho mỗi bộ (giống kỳ thi thật). Hết giờ là dừng, kể cả task đang dở.
- **Không xem đáp án:** chỉ mở `ch17a.html` sau khi hết giờ. Xem trước nghĩa là bạn đang tự luyện đọc hiểu, không phải luyện thi.
- **Tài liệu:** cho phép `kubernetes.io/docs`, tài liệu chính thức của các dự án CNCF liên quan (Helm, Calico, Kyverno, Trivy, cosign, Falco). Không dùng công cụ gợi ý code hay hỏi đáp.
- **Một context duy nhất:** mọi task ghi rõ namespace/cluster; đừng giả định cluster hiện tại là đúng, hãy kiểm tra bằng `kubectl config current-context`.
- **Không phá môi trường:** với task phải sửa static pod (apiserver, etcd), luôn giữ một bản backup manifest trước khi sửa. Task yêu cầu thứ gì thì làm đúng thứ đó, không "sáng tạo" thêm.
- **Tự chứng minh:** mỗi task đều có tiêu chí kiểm tra. Trong phòng thi thật, giám khảo chấm bằng script; nếu bạn không chạy lệnh verify thì rất dễ mất điểm vì lỗi nhỏ (sai namespace, chưa apply).

### Cách chấm điểm {#cach-cham-diem}

Mỗi bộ có tổng 100 điểm, phân bổ theo domain trong bảng ở đầu bộ đề. Chấm theo bước, không "được ăn cả, ngã về không":

| Tình huống | Điểm |
|---|---|
| Hoàn thành đúng và có lệnh verify chạy được | 100% điểm task |
| Sửa đúng nhưng chưa chứng minh (không chạy verify) | 50–70% |
| Chẩn đoán đúng nguyên nhân nhưng chưa sửa xong | 30–50% |
| Làm sai namespace/đối tượng, hoặc còn workload rác | 0% |

Ngưỡng đạt: **CKA 66%**, **CKS 67%**. Quy đổi nhanh:

| Điểm | Đánh giá |
|---|---|
| Dưới 55 | Chưa sẵn sàng; cần ôn lại 2–3 domain yếu nhất trước khi làm lại |
| 55–65 | Sát ngưỡng; lỗi thường nằm ở troubleshooting hoặc kỹ năng gõ lệnh |
| 66–79 | Mức "đậu an toàn"; tiếp tục luyện tốc độ và độ chính xác |
| 80+ | Sẵn sàng đặt lịch thi |

### Tạo cluster và add-on nền {#tao-cluster-va-addon-nen}

Tạo file `ch17-cka-kind.yaml` với control plane mở port 80/443 ra host (host port 8080/8443 để không đụng ứng dụng đang chạy):

```yaml
# ch17-cka-kind.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
name: ch17-cka
networking:
  disableDefaultCNI: true           # tắt kindnet để dùng Calico (enforce NetworkPolicy)
  podSubnet: "192.168.0.0/16"       # khớp default IPPool của Calico
nodes:
  - role: control-plane
    extraPortMappings:
      - containerPort: 80
        hostPort: 8080
        protocol: TCP
      - containerPort: 443
        hostPort: 8443
        protocol: TCP
  - role: worker
  - role: worker
```

Tạo cluster, cài Calico rồi đợi sẵn sàng:

```bash
kind create cluster --config ch17-cka-kind.yaml --image kindest/node:v1.33.1

# Node sẽ NotReady cho tới khi có CNI — đây là hiện tượng bình thường
kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.32.2/manifests/calico.yaml
kubectl -n kube-system rollout status daemonset/calico-node --timeout=240s
kubectl -n kube-system rollout status deployment/calico-kube-controllers --timeout=240s
kubectl get nodes
```

Cài ingress-nginx (chỉ cần cho Set A) và gắn nhãn node cho controller:

```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.15.1/deploy/static/provider/kind/deploy.yaml
kubectl -n ingress-nginx wait --for=condition=available deployment/ingress-nginx-controller --timeout=240s
kubectl label node ch17-cka-control-plane ingress-ready=true
kubectl taint node ch17-cka-control-plane node-role.kubernetes.io/control-plane- 2>/dev/null || true
kubectl get ingressclass
```

### Script dựng đề Set A (CKA) {#script-dung-de-set-a}

Lưu script dưới đây vào `setup-setA.sh` rồi chạy `bash setup-setA.sh`. Script tạo namespace, workload nền và **cố ý** đặt sẵn vài sự cố — đừng mong cluster "sạch".

```bash
#!/usr/bin/env bash
set -euo pipefail

CLUSTER=ch17-cka
W1="${CLUSTER}-worker"
W2="${CLUSTER}-worker2"

# 1) Namespace cho các task
for ns in apps frontend backend storage-a payments search catalog team-alpha; do
  kubectl create namespace "$ns" --dry-run=client -o yaml | kubectl apply -f -
done

# 2) Workload cho task Ingress (A6)
kubectl -n apps create deployment web --image=nginx:1.27-alpine
kubectl -n apps expose deployment web --port=80
kubectl -n apps create deployment api --image=nginx:1.27-alpine
kubectl -n apps expose deployment api --port=80

# 3) Workload cho task NetworkPolicy (A7)
kubectl -n backend create deployment backend --image=nginx:1.27-alpine
kubectl -n backend expose deployment backend --port=80
kubectl -n frontend create deployment frontend --image=nicolaka/netshoot:v0.13 -- sleep infinity

# 4) PVC đang Pending vì storageClass không tồn tại (A8)
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: data
  namespace: storage-a
spec:
  accessModes: ["ReadWriteOnce"]
  storageClassName: standard-rwo
  resources:
    requests:
      storage: 1Gi
EOF

# 5) Deployment Pending vì requests quá lớn (A10)
kubectl -n payments create deployment payments --image=nginx:1.27-alpine --replicas=2
kubectl -n payments set resources deployment payments --requests=cpu=32,memory=128Gi

# 6) DNS bị chặn bởi NetworkPolicy sai selector (A11)
kubectl -n search create deployment api --image=nginx:1.27-alpine
kubectl -n search expose deployment api --port=80
kubectl -n search create deployment client --image=nicolaka/netshoot:v0.13 -- sleep infinity
cat <<'EOF' | kubectl apply -f -
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: lockdown-egress
  namespace: search
spec:
  podSelector: {}
  policyTypes: ["Egress"]
  egress:
    - to:
        - namespaceSelector:
            matchLabels:
              name: kube-system
      ports:
        - protocol: UDP
          port: 53
EOF

# 7) Service không có endpoint: workload lạc namespace và targetPort sai (A12)
kubectl create deployment catalog --image=nginx:1.27-alpine
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Service
metadata:
  name: catalog-svc
  namespace: catalog
spec:
  selector:
    app: catalog
  ports:
    - port: 80
      targetPort: 8080
EOF

# 8) Node cho task scheduling (A5): label + taint
kubectl label node "$W2" disk=ssd
kubectl taint node "$W2" dedicated=gpu:NoSchedule

# 9) Gây sự cố node cho task A9: dừng kubelet trên worker1
docker exec "$W1" systemctl stop kubelet

# 10) Đợi workload baseline lên (trừ các workload cố ý hỏng)
kubectl -n apps wait --for=condition=available deployment --all --timeout=240s
kubectl -n frontend wait --for=condition=available deployment --all --timeout=240s
kubectl -n backend wait --for=condition=available deployment --all --timeout=240s
kubectl -n search wait --for=condition=available deployment --all --timeout=240s

echo "Set A sẵn sàng. Bấm giờ 2 tiếng và bắt đầu làm bài."
```

Kiểm tra nhanh trạng thái "đề đã gài sẵn":

```bash
kubectl get nodes                                  # một worker sẽ NotReady sau ~40 giây
kubectl -n storage-a get pvc                       # data: Pending
kubectl -n payments get pods                       # Pending
kubectl -n search exec deploy/client -- nslookup api.search.svc.cluster.local   # thất bại
kubectl -n default get deploy                      # có deployment catalog lạc namespace
```

### Môi trường cho Set B (CKS) {#moi-truong-cho-set-b}

Set B cần cluster riêng để tránh xung đột với các sự cố của Set A. Tạo lại file kind config với tên `ch17-cks` rồi tạo cluster:

```bash
# Copy cấu hình Set A và đổi tên cluster
sed 's/ch17-cka/ch17-cks/' ch17-cka-kind.yaml > ch17-cks-kind.yaml
kind create cluster --config ch17-cks-kind.yaml --image kindest/node:v1.33.1

# Calico (bắt buộc cho task NetworkPolicy B1)
kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.32.2/manifests/calico.yaml
kubectl -n kube-system rollout status daemonset/calico-node --timeout=240s
kubectl -n kube-system rollout status deployment/calico-kube-controllers --timeout=240s
```

Lưu script dưới đây vào `setup-setB.sh` rồi chạy `bash setup-setB.sh`. Script dựng registry nội bộ, cài Kyverno, tạo workload nền và tạo sẵn vài cấu hình chưa an toàn để bạn phải sửa.

```bash
#!/usr/bin/env bash
set -euo pipefail

CLUSTER=ch17-cks

# 1) Registry nội bộ (giống lab chương 10)
docker rm -f kind-registry 2>/dev/null || true
docker run -d --restart=always -p "127.0.0.1:5000:5000" --name kind-registry registry:3
docker network connect kind kind-registry 2>/dev/null || true

# Cho containerd của mọi node biết registry chạy HTTP
REG_DIR="/etc/containerd/certs.d/kind-registry:5000"
for node in $(kind get nodes --name "$CLUSTER"); do
  docker exec "$node" mkdir -p "$REG_DIR"
  echo 'server = "http://kind-registry:5000"' | docker exec -i "$node" cp /dev/stdin "${REG_DIR}/hosts.toml"
done

# 2) Kyverno v1.17.2 + cho phép registry insecure + hostAlias (giống chương 10)
kubectl apply -f https://github.com/kyverno/kyverno/releases/download/v1.17.2/install.yaml
kubectl -n kyverno rollout status deployment/kyverno-admission-controller --timeout=300s

REG_IP=$(docker inspect kind-registry | jq -r '.[0].NetworkSettings.Networks.kind.IPAddress')
kubectl -n kyverno patch deployment kyverno-admission-controller --type=json \
  -p '[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--allowInsecureRegistry=true"}]'
cat > /tmp/kyverno-patch.yaml <<EOF
spec:
  template:
    spec:
      hostAliases:
        - ip: $REG_IP
          hostnames:
            - kind-registry
EOF
kubectl -n kyverno patch deployment kyverno-admission-controller --type=strategic --patch-file /tmp/kyverno-patch.yaml

# 3) Namespace
for ns in netpol-b secure-rbac hardening pss-lab secure-app; do
  kubectl create namespace "$ns" --dry-run=client -o yaml | kubectl apply -f -
done

# 4) Workload cho NetworkPolicy (B1)
kubectl -n netpol-b create deployment web --image=nginx:1.27-alpine
kubectl -n netpol-b expose deployment web --port=80
kubectl -n netpol-b create deployment api --image=nginx:1.27-alpine
kubectl -n netpol-b expose deployment api --port=80

# 5) Deployment chưa hardening (B6): chạy root, privileged, không RO rootfs
cat <<'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
  namespace: hardening
spec:
  replicas: 1
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      securityContext:
        runAsUser: 0
        runAsGroup: 0
      containers:
        - name: web
          image: nginxinc/nginx-unprivileged:1.27-alpine
          ports:
            - containerPort: 8080
          securityContext:
            privileged: true
            allowPrivilegeEscalation: true
            capabilities:
              add: ["NET_ADMIN"]
EOF

# 6) Deployment vi phạm PSS restricted (B7)
cat <<'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: legacy
  namespace: pss-lab
spec:
  replicas: 1
  selector:
    matchLabels:
      app: legacy
  template:
    metadata:
      labels:
        app: legacy
    spec:
      volumes:
        - name: host-etc
          hostPath:
            path: /etc
      containers:
        - name: app
          image: nginx:1.27-alpine
          securityContext:
            privileged: true
            allowPrivilegeEscalation: true
            capabilities:
              add: ["NET_ADMIN"]
          volumeMounts:
            - name: host-etc
              mountPath: /host-etc
EOF

# 7) Dữ liệu nền cho RBAC, secret và encryption at rest (B3, B4, B8)
kubectl -n secure-rbac create configmap app-config --from-literal=mode=prod
kubectl -n secure-rbac create configmap other-config --from-literal=mode=dev
kubectl -n secure-app create secret generic db-creds --from-literal=password='S3cretValue!'

# 8) Mã nguồn cho task supply chain (B9)
mkdir -p ~/ch17-cks/app
cat > ~/ch17-cks/app/main.go <<'EOF'
package main

import (
    "fmt"
    "log"
    "net/http"
)

func main() {
    http.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintln(w, "ok")
    })
    http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintln(w, "ch17 supply chain demo")
    })
    log.Println("listening on :8080")
    log.Fatal(http.ListenAndServe(":8080", nil))
}
EOF
cat > ~/ch17-cks/Dockerfile.full <<'EOF'
FROM golang:1.24-alpine AS builder
WORKDIR /src
COPY app/main.go .
RUN go mod init demo.local/ch17 && CGO_ENABLED=0 GOOS=linux go build -trimpath -ldflags="-s -w" -o /out/app .

FROM ubuntu:24.04
RUN apt-get update && apt-get install -y --no-install-recommends ca-certificates curl bash && rm -rf /var/lib/apt/lists/*
COPY --from=builder /out/app /app
EXPOSE 8080
CMD ["/app"]
EOF

# 9) Đợi các workload baseline
kubectl -n netpol-b wait --for=condition=available deployment --all --timeout=240s
kubectl -n pss-lab wait --for=condition=available deployment --all --timeout=240s
kubectl -n hardening wait --for=condition=available deployment --all --timeout=240s

echo "Set B sẵn sàng. Bấm giờ 2 tiếng và bắt đầu làm bài."
```

Ghi chú cho Docker Desktop (Windows/macOS): thêm `127.0.0.1 kind-registry` vào `/etc/hosts` (trên WSL2) hoặc bật `insecure-registries: ["kind-registry:5000"]` trong Settings → Docker Engine, giống hướng dẫn ở chương 10.

### Kiểm tra và reset {#kiem-tra-va-reset}

Trước khi bấm giờ, chạy các lệnh sau:

```bash
kubectl config current-context         # kind-ch17-cka hoặc kind-ch17-cks
kubectl get nodes                      # đúng số node, đúng trạng thái "đề"
kubectl get ns                         # đủ namespace theo bộ đề
kubectl cluster-info
```

Sau khi làm xong (hoặc khi muốn làm lại đề sạch):

```bash
kind delete cluster --name ch17-cka
kind delete cluster --name ch17-cks
docker rm -f kind-registry             # dọn registry của Set B
```

Sau đó tạo lại cluster và chạy lại script dựng đề tương ứng — mỗi lần reset, các sự cố được "gài" lại y nguyên.

## Mẹo phòng thi và checklist 15 phút cuối {#meo-phong-thi-va-checklist}

### Phân bổ thời gian và chiến lược làm bài {#phan-bo-thoi-gian-va-chien-luoc}

Kinh nghiệm từ các đề performance-based: người đậu không phải người biết nhiều nhất, mà là người **không bỏ sót task**. Vài quy tắc nên luyện ngay trong mock:

1. **5 phút đầu đọc lướt toàn bộ đề**, đánh dấu task dễ/khó. Làm task chắc chắn trước để "khóa điểm".
2. **Quy tắc 8–10 phút:** task nào vượt quá thời gian gợi ý thì ghi chú trạng thái hiện tại, `kubectl apply` phần đã làm được (đừng để file rời rạc), rồi chuyển task khác. Cuối giờ quay lại.
3. **Đổi context ngay từ đầu mỗi task**, đừng tin vào namespace "đang đứng": `kubectl config set-context --current --namespace=<ns>`.
4. **Tạo resource bằng imperative** (`kubectl create ... --dry-run=client -o yaml > x.yaml`) rồi sửa file — nhanh hơn viết YAML tay và ít lỗi indent.
5. **Verify ngay sau khi làm**, không dồn về cuối: đề thi luôn nói rõ tiêu chí chấm, hãy chạy đúng lệnh chứng minh tiêu chí đó.
6. **Với task troubleshooting, đọc Events trước** (`kubectl describe`, `kubectl get events --sort-by=.lastTimestamp`), sau đó mới suy đoán.
7. **Với cluster-level task (static pod):** backup manifest trước, giữ cửa sổ `docker exec` (kind) hoặc SSH (VM) sẵn sàng, và thay đổi **từng bước một** để biết bước nào gây lỗi.
8. **Đừng làm quá yêu cầu:** tạo thêm resource "cho đẹp" có thể khiến script chấm điểm dương tính giả (ví dụ thừa workload trong namespace bị kiểm tra).

### Checklist 15 phút cuối {#checklist-15-phut-cuoi}

- [ ] `kubectl get nodes` — mọi node `Ready`, đúng cluster của bộ đề.
- [ ] Chạy lại **toàn bộ lệnh verify** ghi trong đề, lần lượt từng task.
- [ ] `kubectl get all -A | grep -v kube-system` — kiểm tra resource có nằm đúng namespace không, có rác ở `default` không.
- [ ] Các Deployment còn dang dở: `kubectl rollout status` / `kubectl rollout history`; pod lỗi: `kubectl get pods -A | grep -vE 'Running|Completed'`.

- [ ] Set B: control plane khỏe sau khi sửa static pod (`kubectl get --raw='/readyz'`), audit log đang ghi, policy Kyverno/PSA enforce đúng, pod đã ký chạy được.

### Những lỗi mất điểm phổ biến {#nhung-loi-mat-diem-pho-bien}

| Lỗi | Hậu quả | Cách phòng |
|---|---|---|
| Tạo resource sai namespace | 0 điểm dù cấu hình đúng | Đổi context ngay đầu task; verify bằng `-n <ns>` |
| Không chạy lệnh verify | Mất 30–50% điểm | Coi lệnh verify là một phần bắt buộc của bài |
| Sửa PVC `storageClassName` | Lỗi immutable, tưởng lệnh hỏng | Nhớ: PVC phải xoá và tạo lại |
| NetworkPolicy default-deny egress nhưng quên DNS | Pod "chết" nhưng tưởng lỗi mạng | Luôn thêm rule DNS UDP/TCP 53 |
| Quên toleration cho node có taint | Pod Pending, mất thời gian | Đọc `kubectl describe node` trước khi gán pod |
| Sửa static pod manifest sai indent | Apiserver không lên, mất cả cluster | Backup + `docker exec` sẵn; sửa từng flag |
| Để lại workload lạc namespace sau khi dọn | Script chấm điểm coi là sai | Kiểm tra `-A` trước khi hết giờ |
| Ingress thiếu `ingressClassName` | Request 404 dù rule đúng | Luôn kiểm tra `kubectl get ingressclass` |

Khi đã làm xong cả hai bộ và điểm ổn định trên ngưỡng, hãy chuyển sang chương tiếp theo — phần phỏng vấn middle/senior DevOps, nơi bạn sẽ dùng chính những kỹ năng này để trả lời câu hỏi tình huống production.
